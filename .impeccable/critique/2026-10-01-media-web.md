# Media Web — visual critique

⚠️ DEGRADED: single-context (`spawn_agent` and the executable Impeccable launcher are unavailable in this session). Review is based on the approved `home-c` comp, fresh Playwright desktop/mobile captures, source inspection, and independent browser accessibility checks.

## Verdict

The interface has a distinct, coherent cinematic identity and avoids the two most likely failure modes for this product: a generic dashboard and a wall of equal Netflix-like cards. The home route reads as an evening screening board, the library becomes denser without changing visual language, and detail pages keep personal signals ahead of provider metadata. The design is ready for finish review after the two bounded detail-page issues found below are verified green.

## Strengths

- **Specificity:** real posters/backdrops dominate chroma; UI surfaces stay near-black/graphite with one tungsten accent. It feels tied to this private film library rather than a generic AI product.
- **Hierarchy:** `Сегодня` has one dominant recommendation, subordinate alternatives, then a quieter `Посмотреть следующим` rail. Library intentionally shifts to denser browsing rather than repeating the hero composition.
- **Information architecture:** `Сегодня → Медиатека → Карточка фильма` is legible, and the visible `Я / Партнёр / Вместе` switcher keeps the household context explicit.
- **Personal signal priority:** ratings, reactions and comments appear before TMDB context on detail pages. No opaque recommendation score was added.
- **Responsive translation:** mobile re-composes rather than mechanically shrinking desktop. Poster grids, filters and detail hero remain usable at 390px.
- **Motion discipline:** entrance/shared transitions add cinematic continuity; reduced-motion removes spatial movement and remains fully usable.
- **Accessibility:** keyboard focus, empty/missing states and WCAG AA axe checks are covered in the browser suite; a previous transient contrast false positive was correctly isolated to an in-flight opacity animation rather than “fixed” by weakening the visual system.

## Findings and resolutions

### P2 — sparse personal-signal layout reserved empty desktop columns

**Observed:** a detail page with only one recorded personal signal still used a three-column grid, leaving a large grey empty field that looked like an unfinished card.

**Resolution:** grid columns now follow the number of actual panels (`1 / 2 / 3`) and collapse to one column on narrow viewports. No missing signal is fabricated merely to fill space.

### P2 — external TMDB score competed with personal impressions

**Observed:** provider values such as `8.272` were rendered at a very large scale. The false precision and size made public popularity feel more authoritative than the household’s own record.

**Resolution:** TMDB display rounds to one decimal and uses a slightly smaller scale. Raw canonical/provider data remains unchanged; only presentation is softened.

## Nielsen / usability notes

- **Visibility of system status:** loading, error, empty and missing states are explicit and in Russian.
- **Match with the real world:** movie metadata and household language are human-readable; canonical vocabulary labels feed recommendation evidence instead of frontend hard-coding.
- **User control:** profile switching is visible and route-aware; v1 clearly remains read-only.
- **Consistency:** shared type, color, radius and focus language holds across all three routes.
- **Error prevention:** no browser write path exists; provider/GitHub credentials are excluded from the static artifact.
- **Recognition over recall:** posters, titles, year/runtime and profile labels remain visible at decision points.
- **Minimalism:** no metric dashboard, duplicated card chrome or decorative blue-purple effects were introduced.

## Persona red flags checked

- **Quick evening chooser:** hero action and alternatives are visible without scanning the full library — passes.
- **Partner / joint context:** switcher is visible and sparse data is not copied from another viewer — passes.
- **Keyboard / reduced-motion user:** focus path and reduced-motion browser tests exist — passes.
- **Mobile user:** 390px captures retain navigation, search/filters and detail readability — passes.

## Finish recommendation

No structural redesign is warranted. Keep polish bounded to the resolved detail hierarchy, then rerun full Web/Media gates and review fresh desktop/mobile captures before documenting the final design system.
