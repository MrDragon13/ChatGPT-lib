# Media Web: продукт

<!-- impeccable:product-schema 1 -->

Технические метки: `Scope: media-web`, `Platform: web`, стек — React + Vite + TypeScript + Motion.

Область документа: `media-web`. Это описание продукта, а не архитектуры всего репозитория.

## Для кого

Основной пользователь — владелец медиатеки. Данные партнёра и совместный контекст дополняют его библиотеку, а не образуют отдельные равноправные продукты.

Сайт рассчитан на личное домашнее использование, а не на публичную аудиторию.

## Зачем нужен Media Web

Media Web даёт наглядный интерфейс поверх личной системы рекомендаций. Через него можно:

- просматривать медиатеку;
- видеть свои и партнёрские впечатления;
- возвращаться к просмотренным фильмам;
- понимать, почему фильм предлагается;
- выбирать, что посмотреть дальше;
- быстро исправлять оценку, реакцию или отзыв.

Подробное добавление новых произведений и обсуждение вкуса по-прежнему удобнее делать в разговоре с LLM. Web дополняет этот путь, а не заменяет его.

## Основные принципы

1. Личные сигналы важнее общей популярности.
2. По умолчанию показывается контекст `primary / Я`; `partner` и `couple` выбираются явно.
3. Web показывает данные из репозитория и не становится вторым источником истины.
4. Выбор фильма должен ощущаться как нормальный вечерний просмотр, а не работа с админкой.
5. Быстрые правки идут через общий типизированный путь записи.
6. Нельзя молча сохранить данные не тому пользователю или группе.

## Технические границы продукта

- Git/YAML остаётся источником истины.
- Производные индексы и профили можно пересобрать.
- LLM, CLI и Web используют один контракт записи.
- Браузер не получает GitHub-токены, ключи провайдера или другие секреты.
- В рабочих компонентах нельзя держать фиктивные массивы фильмов вместо реальных данных.
- Статический сайт должен собираться и работать на GitHub Pages.
- Если Broker недоступен или не настроен, чтение библиотеки всё равно должно работать.
- Рейтинги, реакции и комментарии могут находиться в опубликованном статическом manifest; отдельное шифрование для них не является требованием продукта.

## Визуальное направление

Интерфейс должен быть кинематографичным и аккуратным, а не похожим на типичную панель аналитики.

Netflix и MUBI используются только как ориентир по качеству композиции и ощущению продукта; копировать их интерфейсы не нужно.

Не используем типичные «AI»-градиенты с синим и фиолетовым, а также стены одинаковых карточек.

## Доступность

Минимальный уровень:

- контраст текста по WCAG AA;
- полная работа с клавиатуры;
- видимый фокус;
- поддержка `prefers-reduced-motion`;
- понятные состояния загрузки, ошибки и пустых данных;
- интерфейс на русском, кроме обязательных названий и юридических формулировок провайдеров.
