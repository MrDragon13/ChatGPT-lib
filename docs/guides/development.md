# Разработка ChatGPT-lib

Этот документ описывает изменения кода, схем, архитектуры, workflows, тестов и документации. Обычные пользовательские записи медиатеки идут по пути из `media/AGENTS.md`, а не по этому процессу.

## 1. Начинайте с актуального `main`

Перед работой:

1. проверьте текущий `main`;
2. проверьте открытые PR по той же области;
3. прочитайте `AGENTS.md` и, для media-задач, `media/AGENTS.md`;
4. откройте только те живые документы, схемы и код, которые относятся к задаче.

Исторические specs полезны для понимания причин, но не заменяют текущий код и контракты.

## 2. Выберите правильный путь

### Обычная типизированная операция

Используется для уже поддерживаемых изменений данных: просмотра, оценки, отзыва, интереса, семантики, выведенных предпочтений, interaction и similarity.

Такая запись идёт через существующую JSON Schema и operation PR.

### Developer PR

Используется для изменений:

- domain/service/repository-кода;
- схем;
- контролируемого словаря;
- архитектуры и правил;
- workflows и path policy;
- Broker/Web;
- документации;
- обслуживания и тестов.

Не расширяйте автоматический путь обычной записи ради developer-изменения.

## 3. TDD

Для изменений поведения:

1. напишите тест, который падает по нужной причине;
2. подтвердите RED;
3. внесите минимальное изменение;
4. подтвердите GREEN;
5. запустите полный набор релевантных проверок.

Для документации тестируйте структуру и синхронизацию там, где это полезно: наличие файлов, ссылок, версий, зарегистрированных операций. Не привязывайте тесты к точным формулировкам обычного текста без необходимости.

## 4. Изменение схем и словаря

Schema/vocabulary change — отдельная developer-задача.

Обычная запись данных не должна:

- добавлять поле в схему;
- менять enum или required rules;
- создавать новый термин словаря или synonym;
- ослаблять validation.

Сначала меняются контракт, тесты и правила совместимости/миграции, затем данные.

## 5. Минимальная полная проверка media

```bash
python -m pytest -q
python -m media.tools.validate .
python -m media.cli rebuild --check
python -m media.cli doctor --format json
```

Если изменение затрагивает Web или Broker, добавляются их тесты, typecheck, build, browser и security-проверки по текущим workflows.

## 6. Работа через PR

Для существенной работы используйте отдельную ветку и PR.

В активном PR полезно держать короткий checkpoint:

- что уже сделано;
- точный head SHA проверенного состояния;
- какие проверки прошли;
- что осталось;
- какие решения пришлось принять по ходу работы.

После merge временный журнал PR не переносится в `docs/status/current.md`. Там остаются только устойчивые возможности и ограничения.

## 7. Кто владеет документацией

| Изменение | Что обновить |
| --- | --- |
| типизированная операция | `docs/reference/media-commands.md`; при изменении смысла — нужная архитектурная страница |
| схема или инвариант | `docs/architecture/media-model.md` и/или `docs/reference/invariants.md` |
| рекомендации, вкус, assessment | `docs/architecture/intelligence.md`; пользовательское поведение — `docs/guides/media-usage.md` |
| запись, CI, auto-merge | `docs/architecture/write-pipeline.md`, `docs/guides/operations.md` |
| manifest, Broker, безопасность | `docs/architecture/web-and-broker.md`; при изменении продукта — `PRODUCT.md` |
| структура репозитория | `docs/reference/repository-layout.md` |
| визуальные правила Web | `DESIGN.md` |
| текущее устойчивое состояние | `docs/status/current.md` |
| новое архитектурное решение | датированный файл в `docs/superpowers/specs/`, затем живые документы после реализации |

Если нужная документация не обновлена, изменение считается неполным.

## 8. Перед review

Проверьте, что:

- выбран правильный путь изменения;
- для изменения поведения был RED → GREEN;
- не нарушена граница канонических и производных данных;
- `target` не поменялся незаметно;
- граница секретов не расширилась;
- живая документация соответствует коду, схемам и workflows;
- исторические specs не выданы за текущее состояние;
- в PR есть достаточно информации, чтобы безопасно продолжить работу после паузы.
