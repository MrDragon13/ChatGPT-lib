# Media Intelligence v6 — каталог сценариев агента

Этот документ фиксирует текущие сквозные сценарии v6. Он дополняет `media/AGENTS.md`, но не заменяет его. Имена команд и полей приведены буквально; остальное описано простым языком.

## 1. Отзыв о существующем произведении

Пользователь сообщает просмотр, оценку, реакцию или отзыв о фильме, который уже есть в медиатеке.

Ожидаемое поведение:

1. прочитать `media_entry_context`;
2. взять актуальный viewer digest нужного target;
3. сформировать один `record_media_entry(create_if_missing=false)`;
4. не обращаться к provider;
5. не обновлять metadata;
6. не пересчитывать semantic fingerprint при неизменном semantic input;
7. сразу учитывать свежий явный сигнал в текущем разговоре;
8. говорить «сохранено» только после появления результата в `main`.

## 2. Новое произведение

Если work отсутствует:

1. надёжно установить identity;
2. получить минимальные фактические данные;
3. один раз подготовить semantic snapshot;
4. отправить один `record_media_entry(create_if_missing=true)`.

Создание work, semantics и viewer evidence — одна транзакция. Цепочка `add_work → reread → semantics → feedback` не используется как обычный путь.

## 3. Уточнение по тому же фильму, пока первая запись ещё сохраняется

Если первая операция по work ещё pending, а пользователь сразу уточнил оценку или отзыв:

1. новое уточнение немедленно учитывается в локальном слое текущей LLM-сессии;
2. второй request PR по тому же work/target не создаётся;
3. после authoritative первой операции агент заново читает `media_entry_context`;
4. получает свежий viewer digest;
5. отправляет накопленное уточнение следующей `record_media_entry`.

Web ведёт себя так же: второй submit не отправляется, но локальный черновик не теряется.

## 4. Отзыв партнёра

Target выбирается явно как `partner`. Данные `primary` не используются как будто это мнение партнёра. Повторный анализ вкуса партнёра имеет собственную контрольную точку и собственный счётчик новых содержательных событий.

## 5. Порог повторного анализа 4 → 5

Если у target было четыре новых содержательных события после последнего полного анализа и очередной отзыв создаёт пятое:

1. обычная запись фильма сохраняется независимо от глубокого анализа вкуса;
2. перед следующим запросом, который зависит от вкуса, агент видит `due=true`;
3. сначала выполняет свежий анализ;
4. сохраняет его через `set_inferred_preferences` с evidence checkpoint/digest и algorithm version;
5. только затем выдаёт taste-dependent рекомендацию или assessment.

Retry, `no_change`, metadata-only и косметическая правка summary без изменения явных нормализованных сигналов не увеличивают число событий.

## 6. Рекомендация для пары

У `couple` нет отдельного автоматического счётчика. Перед рекомендацией проверяются статусы `primary` и `partner`. Переанализируется только тот участник, для которого достигнут порог. Разногласие участников не скрывается усреднением.

## 7. Неясная identity или недоступный provider

Если новое произведение нельзя надёжно идентифицировать, canonical work не создаётся. Недоступность необязательных динамических metadata не должна блокировать отзыв о уже существующем work.

## 8. Повтор операции

Повтор одного человеческого события использует тот же `idempotency_key`. Тот же ключ с тем же нормализованным intent не создаёт вторую history event. Тот же ключ с другим intent завершается ошибкой.

## 9. Старый фильм из pre-v6 архива

`docs/archive/media-library-before-v6-reset-2026-10-07.md` используется только как нейтральный чек-лист.

До нового ответа пользователя агент не показывает автоматически старую оценку, реакцию или отзыв. После нового ответа фильм возвращается в активную медиатеку обычным v6-путём.

## 10. Web feedback

Web отправляет feedback через Broker. Broker на точном SHA `main` читает текущий viewer digest, строит `record_media_entry` и создаёт request-only PR. Browser не получает GitHub/provider/model secrets и не вычисляет внутренние preconditions самостоятельно.

## 11. «A похож на B»

Явное сходство записывается через `set_work_similarity`. Связь логически неориентированная. Внешняя сторона связи не создаёт canonical work. Сходство — подсказка/свидетельство для рекомендации и объяснения, а не самостоятельное предпочтение.

Фраза «я больше не считаю A похожим на B» использует `remove_work_similarity`.

## 12. «Мне понравится X?»

Используется read-only `assess_candidate`. Кандидат может быть локальным или внешним. Ответ качественный: без выдуманной точной вероятности и без непрозрачного match score. Неполное основание отражается через coverage/limitations.
