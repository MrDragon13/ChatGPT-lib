# Инварианты media

Короткий список правил, которые должны одинаково соблюдать код, CLI, GitHub Actions, Broker, Web и агент.

1. **Главный источник истины — `main`.** Долговременное состояние media хранится в Git/YAML.
2. **`generated/` можно пересобрать.** Индекс, профили, manifest и временная SQLite-база не становятся каноническими пользовательскими данными.
3. **Обычная запись типизирована.** Пользовательские изменения идут через зарегистрированную typed command, а не через свободную правку YAML.
4. **`target` всегда явный.** `primary`, `partner` и `couple` нельзя смешивать молча.
5. **Неизвестное лучше догадки.** Identity, metadata и vocabulary term остаются неизвестными до надёжной проверки.
6. **Явный сигнал важнее вывода.** Свежие слова пользователя имеют приоритет над inferred interpretation.
7. **Вывод не доказывает сам себя.** Inferred output не становится независимым evidence для следующего вывода.
8. **Семантика произведения не равна реакции зрителя.** Rating, reaction и feedback не являются фактическими traits произведения.
9. **Словарь контролируется.** Обычная операция данных не добавляет новый semantic term скрыто.
10. **Similarity не равно preference.** Явно указанное сходство — основание для рекомендаций, но не устойчивое предпочтение само по себе.
11. **Внешняя ссылка не равна локальному произведению.** Recommendation/candidate/similarity не создаёт work без явного create flow.
12. **Read-only остаётся read-only.** `media_entry_context`, `recommend_context`, `taste_context`, `assess_candidate` не меняют данные.
13. **Один человеческий эпизод — одна обычная запись.** Связанные сигналы по одному произведению по возможности объединяются в `record_media_entry`.
14. **Отзыв о существующем произведении не обращается к провайдеру.** Он не обновляет metadata и не пересчитывает semantics.
15. **Новое произведение создаётся атомарно.** Provider identity, доверенные metadata, semantic traits и пользовательские сигналы применяются одной transaction; технические digests вычисляет runtime.
16. **Viewer digest относится к одному `target`.** Изменения metadata, semantics или другого пользователя не должны его менять.
17. **`no_change` — нормальный успех.** Он не создаёт фиктивную историю и не запускает лишнюю пересборку.
18. **Idempotency относится к человеческому событию.** Тот же `idempotency_key` с тем же intent не дублирует запись; с другим intent операция завершается ошибкой.
19. **Одно событие даёт максимум один новый material evidence.**
20. **Одна косметическая правка текста не двигает анализ вкуса.** `feedback.summary` без изменения структурированных сигналов не продвигает checkpoint.
21. **Checkpoint вкуса основан на digest.** Outstanding evidence считается относительно checkpoint/prefix, а не отдельного изменяемого числа.
22. **Порог проверяется до ответа, зависящего от вкуса.** При достижении порога сначала выполняется reanalysis.
23. **У `couple` нет третьего автоматического счётчика.** Проверяются `primary` и `partner`.
24. **Pending не значит saved.** Свежий сигнал можно учитывать в текущей сессии, но говорить «сохранено» можно только после появления результата в `main`.
25. **Уточнение по тому же произведению не создаёт параллельную запись.** Второй request ждёт завершения первого.
26. **Request PR содержит только request.** До выполнения обычной операции в PR лежит ровно один `.media/requests/<id>.json`.
27. **Path policy узкая.** Обычная операция не может менять schemas, vocabulary, workflows или architecture.
28. **Auto-merge использует один v6 runner.** Все `auto_merge=true` операции используют `v6_single_runner`.
29. **Перед merge повторно проверяется `main`.** Очередь GitHub Actions не заменяет exact base/head guard.
30. **Массовое обслуживание остаётся ручным.** `refresh_metadata` не auto-merge.
31. **Каждый производный результат пересобирается максимум один раз за transaction.**
32. **Сбой провайдера не блокирует отзыв о существующем произведении.**
33. **Архив до v6 только исторический.** Он не является каноническими данными, taste input или источником машинного восстановления.
34. **Пустая библиотека валидна.** Validate, rebuild, doctor, Web и read contexts должны работать при `works=0`.
35. **Глобальные явные предпочтения пережили reset.**
36. **Старые inferred preferences автоматически не восстанавливаются.**
37. **В браузере нет секретов.** GitHub/provider/model credentials не попадают в static bundle.
38. **Broker использует ту же доменную логику.** Browser feedback превращается в `record_media_entry`, а не обрабатывается отдельной бизнес-логикой.
39. **Публичный manifest не показывает внутренние данные синхронизации.** Viewer digests и operation bookkeeping остаются server-side.
40. **`assess_candidate` остаётся качественным.** Никакой псевдоточной вероятности или непрозрачного match score.
41. **`limitations` влияют на вывод.** Нельзя скрывать нехватку данных ложной уверенностью.
42. **Developer PR требует полной проверки.** Один focused test недостаточен для финального success claim.
43. **Исторические specs объясняют, но не управляют.** Они не переопределяют текущий код, схемы, `AGENTS.md` и живые документы.
44. **Откат после cutover не должен уничтожать новые данные.** После появления новых v6-записей слепой revert запрещён; нужна forward migration.
